# Machinedrum Editor + Monomachine Editor 0.9.0

The sample release. The Machinedrum gets a sample manager, the Monomachine gets a DigiPRO waveform manager, and a SysEx import or an Empty Reset can be undone. Two long-standing faults are closed: the Monomachine's OJMP value and the song LOOP row.

A release on top of [0.8.1](https://github.com/radekdymacz/mdmm/blob/main/doc/release/v0.8.1.md). Screenshots, features and FAQ: **https://mdmm.dev** · User guide: **https://mdmm.dev/guide/**

## New, Machinedrum
- **Sample manager.** On the Sampler workspace, on the emulated machine, every ROM and RAM slot shows its length in seconds and in KB. The card above the tiles shows the memory as the machine counts it: used, free and the percent free.
- **Copy and Paste.** Copy a ROM or RAM slot, select a ROM slot, paste. The copy is taken when you press Copy, so a RAM take is kept even if the recorder overwrites it.
- **RAM to ROM.** Every RAM slot with a take has **Keep as ROM...**: the take is sent to the selected ROM slot. This is FUNCTION + REC on the machine. The other RAM slots are not cleared.
- **Rename and Load keep working** and are now part of the same undo.
- **Undo sample.** One key brings back the sample that a Paste, a RAM to ROM copy, a Rename or a Load replaced. Sixteen steps. A step that filled an empty slot cannot be undone; erase the slot instead (see Erase).
- **Export.** A ROM slot to a WAV file or to SysEx (SDS), a RAM slot to a WAV file, **Export all** for the ROM slots or the four RAM slots to a folder. The files hold the samples the machine holds, 16-bit mono at the slot's own rate.
- **Erase one and Erase all** (B-194). A ROM slot can be erased, or all of them. The editor presses the machine's own keys for it (SAMPLE MGR, ERASE) and checks the bank afterwards. Undo sample brings back one erased slot. Erase all cannot be undone, as 32 slots are more than the 16 steps, and the question says so.
- A real Machinedrum on hardware MIDI keeps its limits: it does not answer sample dump requests, so these keys are off there, each with its reason.

## New, Monomachine
- **DigiPRO manager** (MKII). On the GLOBAL page the DigiPRO card shows the 64 positions W01 to W64. A user waveform is marked **u** with its name and is drawn when selected. The card has **Read**, **Load...** (a `.syx`, or a WAV or AIFF of one cycle; the editor asks first), **Save .syx...** (Shift for all), **Rename**, **Copy**, **Paste**, **Erase** (Shift for all, asked first) and its own **Undo**. Factory waveforms cannot be saved, renamed or erased, as on the machine.
- **Export SysEx > Waveforms** puts the user waveforms into a bank file.
- **AUTO RECEIVE** (I-070). A kit, pattern, song or global dump sent from the DAW (a MIDI track, a Max for Live device) now lands on the emulated Monomachine, as it does on the Machinedrum. Turn on **AUTO RECEIVE** in the engine menu: the editor opens GLOBAL > FILE > SYSEX RECV itself when such a dump arrives, sends it as IMPORT SYSEX does, and goes back to the main screen. Off by default, so the machine behaves as the hardware does; kept with the project. One undo step per burst. The emulator only: with a real Monomachine on hardware MIDI, open SYSEX RECV on the machine.
- **Song LOOP** (B-038). A LOOP row in a song now goes to the row it names. The editor wrote the target in the wrong byte, so every loop went back to row 1.

## New, both editors
- **Undo for SysEx import and Empty Reset** (B-130). The kits, patterns and songs a job will write are copied first. When the job is over they are one undo step, and Redo brings the import back. Factory reset is covered the same way.
- **No false "edits not saved" question on the Machinedrum** (B-045). A pattern picked while an import runs no longer asks about kit edits you never made.
- **Save Diagnostics.** The editor's menu has **Save Diagnostics...**. It writes one zip with the logs, the versions, the system, the audio and MIDI setup, the settings and the last performance capture. It never holds a ROM or the machine's memory. Attach it to a report in #bugs or send it from the contact page. It is made by the program itself, so it works when the page does not show.
- **Third-party notices.** `THIRD-PARTY-NOTICES.md` is in every package and named in the About box, with the licences of the code the editors are built on.

## Fixes
- **Monomachine: OJMP** (B-189). The editor wrote OJMP to bits 4 to 7 of the arpeggiator's play byte, and the firmware keeps it in bits 3 to 6. The machine then read 2n+1 for a value n. A firmware test now proves the layout. See Upgrade.
- **Monomachine: a DigiPRO job no longer leaves its position empty or hangs the machine** (B-195). Two causes: the emulated machine stops for good when a status poll arrives while it sends a waveform, so the editor now asks nothing until the dump is in; and the SYSEX RECV page could wait for a job that waited for it.
- **Monomachine: a new kit starts with the machine's values** (B-176) is checked on the firmware.
- **Audio thread: shorter lock holds** (B-203). The factory flash is copied after the device lock, and the machine-memory copy no longer holds the device lock while audio runs. A save reaches its file a look or two later at most. The sound is unchanged.
- **Machinedrum: a tempo change right after a nudge keeps the new tempo** (B-200). On a slow machine a late read of GLOBAL used to put the old tempo back.
- **Machinedrum: Erase works from any screen** (B-204). It looks only at the GLOBAL SLOT window, so the main screen around it no longer matters, and a RAM take is copied again once it is complete.
- **Monomachine: two quick edits of a song row** (B-202) no longer wait for a read-back that is never asked.
- **Linux: the empty window** (B-201, Fedora KDE). The web view's helper turns off WebKit's DMA-BUF renderer and compositing, realizes, maps and sizes its window before it is embedded, and the host maps a hidden client. If the page still never paints, the native card appears. The log names the GTK and WebKitGTK versions. Not yet proved on Fedora: please try it.
- **Guide:** 22 of 25 stated facts were checked against the machine, three wrong claims are corrected, the CTR-AL limit is gone (kits with a CTR machine edit since 0.6.0), and the FN key tips say that the FN latch has been gone since 0.3.5.
- **Release files:** the SHA256SUMS and other-platform jobs find the draft by the id the macOS job made.

## Upgrade
- **Monomachine OJMP: old projects keep their sound.** The machine's bytes are unchanged. Only the editor's reading changes: it now shows the value the machine plays. A project saved with OJMP 3 may show another number now, and the sound is the one you always heard. Set the number you want, and it is what the machine plays.
- The JSON member `flag` of the Monomachine data contract is gone (it was OJMP's low bit).

## Known
- **Monomachine: LIVE RECORDING can record no lock after the GLOBAL base channel was changed** (B-196). It is parked until after 0.9.
- **Hardware MIDI is beta.** Using the editor with a real Machinedrum or Monomachine over MIDI works, but it is tested only in part. It will be tested on both machines before 1.0.
- **Windows and Linux are community-tested.** They are built and run by the tests on every change, and no person has tested every release. Please send your logs with Save Diagnostics.
- **Machinedrum: after a sample is sent by SDS, live recording records nothing until you restart the editor** (B-133). The machine's OS 1.63 bug; the editor keeps the hardware's behaviour.
- **Monomachine: a GLOBAL change made while the editor is still reading the machine at project open may not reach the memory file** (B-192).
- **Control matrix: the lanes are MIDI Learn routes** (CC 21 to 28 by default), not host parameters. Map the targets in the DAW: turn the value itself on the page and map `Track 1 Machine Parameter 3`. Host-mappable Knob 1 to 8 come in 0.9.1 (B-205).
- **Monomachine: two factory patterns did not play in one real-factory journey** (B-198) and **one 10.4 ms device-lock hold in a test** (B-199). Each was seen once and is open; nothing a user reported.
- **Two journeys, `mm-song-row-settings` (B-202) and `md-sound-knob-steps` (B-193), failed once each in CI.** Fixes are in; neither has been seen in use.
