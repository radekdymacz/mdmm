Machinedrum Editor + Monomachine Editor 0.5.0

Released 2026-10-10

A release on top of 0.4.0: the Monomachine Editor at the Machinedrum Editor's level, less emulation work, fixes from your reports, and a project that no longer depends on the fork it came from.

Screenshots, features and FAQ: https://mdmm.dev · User guide: https://mdmm.dev/guide/

The Monomachine catches up

  • A GLOBAL page (Monomachine Editor, B-051). The GLOBAL key in the top bar, or GLOBAL… in the engine menu, opens the same panel the Machinedrum Editor has: the 8 global slots (a click makes one active), Control (base channel, channel span with each track's channel shown, auto track, multi trig, multi map, program change in and out), Sync (tempo and transport in and out) and Routing. Each change is stored in the active global and made active. Both editors' panels get Reset to defaults (asked first), which writes the global the machine ships with.
  • Sound edits reach the machine whatever the global's MIDI channels (Monomachine Editor, B-051). After importing a backup with its globals, turning values on the page could change nothing: the imported global had CHANNEL SPAN 0, so no track had a MIDI channel of its own. A value for a track without a channel now goes as a kit dump. A mute or note that cannot reach a track shows a notice with one key, Give each track its own channel. The SysEx import window's Globals tab says that importing a global changes the channels the machine listens on.
  • Step selection as on the Machinedrum (Monomachine Editor). ⌘-click or ⌘-drag (Ctrl on Windows and Linux) in the piano roll, a trig row or the step ruler selects steps; ⌘C, ⌘X, ⌘V, ⌘D and ⌘A copy, cut, paste, duplicate and select all; ← and → move the selection, Shift with them extends it; a ⌘-drag of the selection drops a copy. Delete and the LCD's COPY, CLR and PASTE act on the selection. A right-click opens the step menu: note on or off, NOTE OFF, trigless, slide, a chord note, copy, cut, paste here, duplicate, clear, and fill every 2nd or 4th step (moved there from ⌘-click).
  • Notes in the piano roll have a length (Monomachine Editor, I-010). A new note lasts the draw length (the Len key: 1/16, 1/8, 1/4, 1/2, 1 bar), and dragging a note's end sets it, as in Ableton. A note on a synth track writes its trig and a NOTE OFF where it ends; on a MIDI track it writes its LEN (6 a step, measured on the firmware; the roll assumed 8). The roll draws a note up to the track's next trig, and past the pattern's end onto its start, lighter. Deleting a note leaves the note before it its length.
  • Draw and box select in the piano roll (Monomachine Editor, I-007). B on Sequence, or the Draw key, turns drawing on and off. With it off, a drag in an empty place boxes notes into the selection, a press on a note selects it, a drag moves the selection (one undo step), and a double-click adds a note.
  • Tap tempo is Shift+B on every workspace of both editors. On the Monomachine, B is Draw on Sequence and still taps elsewhere; the Machinedrum keeps T and B.
  • Live recording shows what it locks (Monomachine Editor). While LIVE RECORDING plays, a value you turn is locked on the step that plays. The editor marks that step's cell and lock lane for 3 s and says which value it locked.
  • The keyboard view is complete (Monomachine Editor): the zoom keys, tips and pointer gestures the Machinedrum lists, where the Monomachine has them.
  • The Sound page and GEN / MUTATE as on the Machinedrum (Monomachine Editor). Both editors now draw the Sound rows and the GEN and MUTATE bars from one source. Cmd or Ctrl-click on the R key randomises the track, as on the Machinedrum. At 1440 x 900, R and Defaults no longer fall off the GEN bar.
  • The editor follows the kit the machine plays after a pattern pick (Monomachine Editor, B-053, B-046). The Monomachine's OS 1.32B loads a pattern's linked kit only for a pattern in banks A to D; in banks E to H the kit that played goes on, from the editor or from the panel. The editor asked about losing unsaved kit edits before an E-H pick, which was false, and the first edit in the piano roll then made the machine load the linked kit, and your edits were gone. Now the question comes only for an A-D pattern, and an edit of the pattern that plays keeps the kit that plays. The page says "The pattern now links K001, the kit that plays" (with the kit's number). This also explains B-046: picking H16 of a backup leaves the machine on the kit that played.

Faster

  • Less emulation work again (both editors). The emulated DSPs skip more of the turns of their idle loops: the silent-voice NOP loops, the loops that wait on a DMA register, the Machinedrum's two sync waits and the Monomachine's Port C wait. Host cycles per audio frame against 0.4.0's code: the Machinedrum 3.7 % less stopped and 2.8 % playing, the Monomachine 18.7 % and 6.2 %. The last idle-loop change took a further 7.0 % and 6.5 % off the Machinedrum and 2.1 % and 3.6 % off the Monomachine. Every one of these is bit-exact: the sound is the same, bit for bit.
  • The macOS build is optimised with a recorded profile (PGO). On top of the above, host cycles per frame: the Machinedrum about 7.5 % less, the Monomachine 5 to 6 %. The sound is the same, bit for bit. Windows and Linux builds do not have it.
  • All of it together, measured against 0.4.0: per audio frame the Machinedrum needs about 19 % less work stopped and 16 % less playing, the Monomachine about 27 % less stopped and 18 % less playing (retired instructions; host cycles agree within a few points). The same sound, bit for bit. Measured on an M4 Pro, outside a DAW; not yet checked in a DAW or on an M1.
  • To compare, the speed-ups are on by default and Developer > Speed-ups off (legacy emulation, slower) in the right-click menu, or GEARMULATOR_MDMM_SPEEDUPS=0 before you start your DAW, turns them all off. Both give the same sound. If a click or a timing difference goes away with them off, tell us.
  • An experiment, off by default: Developer > Exact MD audio timing (experimental, changes the sound) (Machinedrum Editor only, or GEARMULATOR_MDMM_EXACT_ESSI=1). It wakes the Machinedrum's DSPs at the exact cycle of each audio slot. It saves some more CPU (measured before the last idle-loop change: 7.4 % fewer host cycles per frame stopped, 3.2 % playing), but it moves notes and DSP work by microseconds, so the Machinedrum sounds slightly different. It acts only while the speed-ups are on.
  • Fewer spikes on the audio thread (both editors). The Machinedrum Editor's sample list was built on the audio thread, with 143 allocations and up to 128 µs for one sample slot in a block. The audio thread now only copies the memory, at most 13 µs a block, and the editor builds the list. At host sample rates other than 44.1 kHz, each plug-in held 8 copies of the resampler's filter (4.8 MB); now there is one per process (0.34 MB) and the resampler takes about 40 % less time. Both bit-exact.

Fixes

  • The Monomachine Editor draws the amp envelope the machine plays (B-049). A tester on Discord said the amp envelopes looked wrong. The values reached the machine as sent; the pictures were a guess. Measured on the firmware: ATK, DEC and REL are times, not steps of the tempo, and grow about twice every 8 to 10 values (ATK 64 reaches 90 % in 0.14 s, where the page drew 1 s; DEC 96 falls 20 dB in 4.7 s, where it drew 1.5 s; REL 127 never fades). Only HOLD followed the tempo. Sound › Amp, the TRIG SETUP plate and the piano roll's bars now draw from the measured times.
  • A piano-roll note no longer puts another track's sound back (Monomachine Editor, B-050). A tester on Discord saw this on 0.3.5. It is B-027, fixed in 0.4.0; a firmware test now checks it.
  • The AU no longer opens the old Gearmulator screen (macOS, B-048). A user on Discord got upstream's old panel when loading an editor as an AU in Ableton Live. Our AU only shows the editor page: an old preview build was still installed, and it registers the same Audio Unit codes with a higher version, so macOS used it. The installer removed old copies by name only; it now also removes a copy at any name in the plug-in folders it searches, when it carries our codes and is ours. The .dmg's and zip's install texts say an old AU can take the new one's place.
  • macOS 12: the Sound page lays out as it should (both editors, B-055). macOS 12's web view (WebKit 15) has no subgrid and no :has(): on the Sound page each group's title sat at the top of a tall row and a short screen at its foot. Four smaller places used :has() too (the Machinedrum's Sampler set-up card, the GEN tag beside a track's name, the GEN bar's summary, the Monomachine's Perform assign rows without a joystick). None is left; every view of both editors is now checked as WebKit 15 lays it out. Not yet tried on a Mac with macOS 12.
  • The GEN bar keeps R and Defaults in view (Monomachine Editor, B-056). In a window smaller than 1440 x 720 the page is zoomed out and the web view raises small text, which pushed the keys off the bar's end. The bar now tightens its spacing and labels in steps until everything fits.
  • The DSP bridge and the MCP server are gone (both editors). The MCP server (upstream's remote control for AI tools, off by default) and the DSP bridge (upstream's network DSP, with no switch in these editors) are removed. A project saved by an upstream build with the bridge on still loads, on the local machine.

A project of its own

  • The editors no longer depend on the fork they came from. The emulator cores (DSP56300 and 68k), JUCE and RmlUi are folders in this repository, so the build no longer needs the fork's accounts (only freetype and lunasvg are still fetched from their own projects). The other synths, VST2, CLAP and LV2, upstream's tools and workflows, the DSP bridge and the MCP server are deleted: outside the emulator cores and the frameworks, about 200,000 lines of C and C++, almost half.
  • Nothing you use changed: the same bundle names, identifiers, AU codes and VST3 class IDs, so a DAW finds the editors where it did and old projects load. The sound is the same, bit for bit, on both machines with the speed-ups on and off.
  • Credits stay: the project grew out of joelanders' Machinedrum and Monomachine emulation, built on Gearmulator by The Usual Suspects and contributors (README).

Known

  • A project with a damaged flash image can hang the audio thread (B-054). Seen once, in a test that damaged a project on purpose; not seen with a real project.
  • The start-up card's animation may be skipped now and then on a second start (B-052). Seen in a test on a loaded Mac; not seen by a user.
  • Monomachine GLOBAL: master tune is not on the page yet, and some bytes of the global are still not decoded.
  • The AU version is still below the old preview builds' 2.2.9 (B-048). A left-over old AU the installer cannot see (another user's home folder, a subfolder, a disk-image install) still wins. If your DAW opens the old panel, tell us what is in /Library/Audio/Plug-Ins/Components and ~/Library/Audio/Plug-Ins/Components.
  • Machinedrum: a pattern pick during a SysEx import asks about unsaved kit edits you never made (B-045). It goes away when the import finishes.
  • Monomachine: a LOOP row in a song written by the editor goes back to row 1 (B-038).
  • Drag and drop works on macOS only (I-017). On Windows and Linux, use the buttons.
  • The update banner still offers Download (the site), never Update. Installing from inside the app waits for our update signing key (I-005).

For developers

  • The repository is radekdymacz/mdmm (renamed from gearmulator-md-mm; old links redirect). Apps up to 0.4.0 accept only the old download prefix in latest.json, so it keeps it; apps from 0.5 accept both.
  • One product set, no submodules but freetype and lunasvg. No per-synth switches; upstream's remotes, sync script and Jenkins files are gone. Upstream fixes are copied one commit at a time (doc/release/PLAN-0.5.md). What "unchanged" meant and how it was checked: doc/release/CLEANUP-BASELINE.md.
  • PGO: a committed, firmware-free text profile (source/elektron/md/pgo/), applied to both macOS slices by the release build, CI and the local gate; CI never trains it and needs no ROM.
  • Old WebKit checks: the journeys md-old-webkit and mm-old-webkit compare every view as WebKit 15 lays it out; scripts/mdmm-snap.py takes page snapshots without Screen Recording (--safari15 --size WxH --check).
  • Windows CI: the machine MIDI out tests run there again (B-047, a test-only fault).

Platforms

  • macOS 12 or later (Intel and Apple silicon), not signed by Apple yet: the first install needs Open Anyway (on macOS 12 to 14: right-click the installer > Open).
  • Windows x64 and Linux x64: not tested by a person yet. Feedback welcome: https://mdmm.dev/contact/
